# Lookup cost

What a name lookup costs, measured against the usual alternatives, and what the generated
tables cost to compile. The numbers come from `bench/bench.cc` and `bench/compile_time.cc`; the
benchmark checks every row's answer (identity for each member, no false accept for a near miss)
before it times anything.

## Setup

| | M4 | i9 |
| --- | --- | --- |
| CPU | Apple M4 Pro | Intel Core i9-9980HK, 2.4 GHz |
| OS | macOS 26 | macOS 15 |
| Compiler | Apple clang 17.0.0, libc++ | Apple clang 17.0.0, libc++ |
| Abseil | 20260817.0 (Homebrew) | Homebrew build in `/usr/local` |

```sh
cmake -B build -DCMAKE_BUILD_TYPE=Release -DENUM_REFLECTION_BUILD_BENCH=ON
cmake --build build --target enum_reflection_bench
build/enum_reflection_bench
```

Each row is the median of nine runs of about a million lookups, cycling through the names in a
shuffled order, on a machine reserved for the measurement. The table rows are the median of three
rounds, and the comparators run in the same process as the library. The enums are generated by
`bench/gen_enums.py` into `bench/enums.h`: dense enums of 8, 32 and 128 members (values 0 to N-1)
and a sparse one of 32. Abseil is optional; without it the `absl::flat_hash_map` rows are absent.

## A name to its value, `enum_type`

Hit: the name is a member. Miss: it is not, answered with `enum_try_type`. The map is
`absl::flat_hash_map<std::string_view, int>`. The linear scan compares the names in order, the
sorted array is a binary search over `(name, value)` pairs. Times are ns per lookup.

| members | machine | `enum_type` hit | linear scan | sorted array | `absl` map | `enum_try_type` miss | `absl` miss |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | M4 | 3.2 | 1.0 | 11.1 | 4.6 | 3.0 | 1.8 |
| 8 | i9 | 7.5 | 2.8 | 19.0 | 11.2 | 6.2 | 4.7 |
| 32 | M4 | 3.4 | 17.2 | 16.6 | 4.8 | 2.9 | 2.2 |
| 32 | i9 | 7.6 | 43.1 | 30.6 | 11.2 | 5.9 | 4.8 |
| 128 | M4 | 3.3 | 62.2 | 23.4 | 4.3 | 2.8 | 2.1 |
| 128 | i9 | 7.3 | 158.9 | 63.1 | 12.3 | 6.3 | 5.0 |
| 32 sparse | M4 | 3.4 | 17.6 | 16.4 | 4.4 | 2.9 | 2.0 |
| 32 sparse | i9 | 7.8 | 45.1 | 32.6 | 11.2 | 6.2 | 4.4 |

- A hit costs less than the hash map's at every size: 3.2 to 3.4 ns against 4.3 to 4.8 on the M4,
  7.3 to 7.8 against 11.2 to 12.3 on the i9. The map answers a miss 1.2x to 1.7x faster at every
  size, and a miss costs about what a hit does.
- A linear scan is the fastest way to find a name among 8, and falls behind from 32 on.
- The lookup allocates nothing and builds no table at run time; the hash map does both.

## A value to its name, `enum_name`

| members | machine | `enum_name` | array by value | binary search by value |
| ---: | --- | ---: | ---: | ---: |
| 8 | M4 | 1.4 | 0.3 | 1.9 |
| 8 | i9 | 3.4 | 0.4 | 2.6 |
| 32 | M4 | 1.4 | 0.3 | 3.5 |
| 32 | i9 | 3.1 | 0.5 | 4.9 |
| 128 | M4 | 1.6 | 0.3 | 5.8 |
| 128 | i9 | 3.8 | 0.5 | 6.7 |
| 32 sparse | M4 | 1.4 | n/a | 3.5 |
| 32 sparse | i9 | 3.1 | n/a | 5.0 |

An array indexed by value is 4x to 8x faster, and exists only for dense values. `enum_name` does
not depend on the values being dense and costs about the same from 8 to 128 members.

## The two enums of `bench.cc`

A method-like enum and a status-like enum of 14 names each, ns per lookup.

| lookup | M4 method | M4 status | i9 method | i9 status |
| --- | ---: | ---: | ---: | ---: |
| `enum_type`, exact case, hit | 2.2 | 2.5 | 5.4 | 5.9 |
| `enum_try_type`, hit | 2.4 | 2.8 | 5.5 | 6.5 |
| `enum_try_type`, lower case, hit | 2.4 | 3.4 | 5.5 | 7.8 |
| `enum_try_type`, miss | 2.1 | 2.4 | 4.8 | 5.2 |
| `enum_type`, miss (throws) | 2007 | 2167 | 3946 | 4235 |

A miss that throws costs several hundred times a hit; code that expects misses calls
`enum_try_type`.

## What a lookup checks

A hit is confirmed against the member's name, not only its 64-bit hash, so a string that collides
with a member's hash is rejected. The check is part of the cost above: the input is read once, with
wide loads, and the same words give its hash and are compared with the member's entry, whose name
is lower-cased the same way (see [ARCHITECTURE.md](../../ARCHITECTURE.md)). The benchmark feeds each
enum about eight near misses per member (one letter changed, skipping strings that equal a member's
name up to case) and requires that none is accepted. `test/names_test.cc` covers forged collisions,
and `test/mutants.py` shows that each part of the check is needed.

The case of the input does not change the cost of a name of up to 16 bytes. Longer names are
compared with their exact bytes first, so a lower-case hit of one costs a little more (the `Status`
column of the table above).

## Compile time

The accessors of the four enums above (8, 32, 128 and 32 sparse members: 200 names) in one
translation unit, against a translation unit that only includes the enums' header, built with
`c++ -std=c++20 -O2 -c`, best of two runs, inside the A/B hold with other builds running on the
machine.

| | M4 | i9 |
| --- | ---: | ---: |
| header only | 1.1 s, 208 B | 1.1 s, 208 B |
| four enums | 5.0 s, 49.8 KB | 5.1 s, 49.7 KB |

The tables are built by the compiler, so the cost is paid per translation unit that instantiates
an enum's accessors: about 25 ms per name. To time it,
`cmake --build build --target enum_reflection_ct_base enum_reflection_ct --clean-first`.
