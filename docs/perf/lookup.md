# Lookup cost

What a name lookup costs, measured against the usual alternatives, and what the generated
tables cost to compile. The numbers come from `bench/bench.cc` and `bench/compile_time.cc`; the
benchmark checks every row's answer (identity for each member, no false accept for a near miss)
before it times anything.

## Setup

| | M4 | i9 |
| --- | --- | --- |
| CPU | Apple M4 Pro | Intel Core i9-9980HK, 2.4 GHz |
| OS | macOS 26 | macOS 15 |
| Compiler | Apple clang 17.0.0, libc++ | Apple clang 17.0.0, libc++ |
| Abseil | 20260817.0 (Homebrew) | Homebrew build in `/usr/local` |

```sh
cmake -B build -DCMAKE_BUILD_TYPE=Release -DENUM_REFLECTION_BUILD_BENCH=ON
cmake --build build --target enum_reflection_bench
build/enum_reflection_bench
```

Each row is the median of nine runs of about a million lookups, cycling through the names in a
shuffled order, on an otherwise idle machine. Two full runs agree within 15% on every row (the
throwing rows excluded). The enums are generated by `bench/gen_enums.py` into `bench/enums.h`:
dense enums of 8, 32 and 128 members (values 0 to N-1) and a sparse one of 32. Abseil is
optional; without it the `absl::flat_hash_map` rows are absent.

## A name to its value, `enum_type`

Hit: the name is a member. Miss: it is not, answered with `enum_try_type`. The map is
`absl::flat_hash_map<std::string_view, int>`. The linear scan compares the names in order, the
sorted array is a binary search over `(name, value)` pairs. Times are ns per lookup.

| members | machine | `enum_type` hit | linear scan | sorted array | `absl` map | `enum_try_type` miss | `absl` miss |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | M4 | 4.1 | 1.0 | 11.0 | 5.0 | 2.9 | 1.9 |
| 8 | i9 | 11.8 | 3.2 | 21.5 | 11.8 | 9.3 | 4.6 |
| 32 | M4 | 4.8 | 17.6 | 16.3 | 4.5 | 3.1 | 2.3 |
| 32 | i9 | 12.7 | 43.0 | 33.6 | 12.1 | 9.2 | 5.0 |
| 128 | M4 | 8.4 | 64.1 | 23.1 | 4.8 | 3.2 | 2.4 |
| 128 | i9 | 20.0 | 178.6 | 62.0 | 13.5 | 9.9 | 6.0 |
| 32 sparse | M4 | 4.8 | 19.0 | 17.1 | 4.8 | 3.2 | 2.1 |
| 32 sparse | i9 | 11.4 | 48.6 | 32.9 | 12.3 | 8.7 | 5.3 |

- Up to 32 members a hit costs the same as the hash map's. At 128 members the hash map is
  1.5x (i9) to 1.7x (M4) faster, and it answers a miss 1.5x to 2x faster at every size.
- A linear scan is the fastest way to find a name among 8, and falls behind from 32 on.
- The lookup allocates nothing and builds no table at run time; the hash map does both.

## A value to its name, `enum_name`

| members | machine | `enum_name` | array by value | binary search by value |
| ---: | --- | ---: | ---: | ---: |
| 8 | M4 | 1.4 | 0.3 | 1.9 |
| 8 | i9 | 3.7 | 0.5 | 3.2 |
| 32 | M4 | 1.4 | 0.3 | 3.5 |
| 32 | i9 | 3.6 | 0.4 | 5.5 |
| 128 | M4 | 1.8 | 0.3 | 6.1 |
| 128 | i9 | 4.0 | 0.5 | 5.2 |
| 32 sparse | M4 | 1.5 | n/a | 3.7 |
| 32 sparse | i9 | 3.7 | n/a | 3.9 |

An array indexed by value is 4x to 8x faster, and exists only for dense values. `enum_name` does
not depend on the values being dense and costs about the same from 8 to 128 members.

## The two enums of `bench.cc`

A method-like enum and a status-like enum of 14 names each, ns per lookup.

| lookup | M4 method | M4 status | i9 method | i9 status |
| --- | ---: | ---: | ---: | ---: |
| `enum_type`, exact case, hit | 4.4 | 4.5 | 10.7 | 10.9 |
| `enum_try_type`, hit | 4.5 | 4.0 | 9.9 | 10.6 |
| `enum_try_type`, lower case, hit | 4.7 | 5.9 | 13.6 | 18.9 |
| `enum_try_type`, miss | 3.5 | 3.8 | 8.8 | 9.4 |
| `enum_type`, miss (throws) | 2200 | 2357 | 4363 | 4699 |

A miss that throws costs several hundred times a hit; code that expects misses calls
`enum_try_type`.

## What a lookup checks

A hit is confirmed against the member's name, not only its 64-bit hash, so a string that collides
with a member's hash is rejected. The benchmark feeds each enum about eight near misses per
member (one letter changed, skipping strings that equal a member's name up to case) and requires
that none is accepted. `test/names_test.cc` covers forged collisions.

## Compile time

The accessors of the four enums above (8, 32, 128 and 32 sparse members: 200 names) in one
translation unit, against a translation unit that only includes the enums' header, built with
`c++ -std=c++20 -O2 -c`, three runs each.

| | M4 | i9 |
| --- | ---: | ---: |
| header only | 0.4 s, 336 B | 1.2 s, 208 B |
| four enums | 4.9 to 5.2 s, 57.7 KB | 15.7 to 16.8 s, 58.5 KB |

The tables are built by the compiler, so the cost is paid per translation unit that instantiates
an enum's accessors: about 25 ms per name on the M4 and 75 ms on the i9. To time it,
`cmake --build build --target enum_reflection_ct_base enum_reflection_ct --clean-first`.
